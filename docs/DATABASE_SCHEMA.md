# Database Schema

# FinShield AI
## Intelligent Fraud Detection & Money Flow Investigation Platform

---

# Purpose

This document defines the MongoDB collections used in FinShield AI.

The database is designed to support:

- Banking Transaction Simulator
- Fraud Detection Engine
- AI Risk Prediction
- Graph Investigation Engine
- Fraud Case Management
- Alert System
- Audit Logging

---

# Database Collections

1. Users
2. Accounts
3. Transactions
4. Fraud Analysis
5. Risk Profiles
6. Fraud Cases
7. Alerts
8. Audit Logs

---

# Database Relationship

User
│
├── One User → Many Accounts
├── One User → Many Transactions
├── One User → One Risk Profile
├── One User → Many Alerts
└── One User → Many Fraud Cases

Transaction
│
└── One Transaction → One Fraud Analysis

Fraud Case
│
├── References User
├── References Transaction
└── Assigned to Fraud Analyst

# 1. Users Collection

## Purpose

Stores authentication and profile information for all users.

Users can have three roles:

- Customer
- Fraud Analyst
- Admin

### Fields

| Field | Type | Description |
|--------|------|-------------|
| _id | ObjectId | User ID |
| fullName | String | Full name |
| email | String | Login email |
| password | String | Hashed password |
| phone | String | Mobile number |
| role | String | customer / analyst / admin |
| status | String | active / blocked |
| createdAt | Date | Created date |
| updatedAt | Date | Updated date |

# 4. Fraud Analysis Collection

## Purpose

Stores fraud analysis results for each transaction.

Keeping this separate from Transactions ensures the original financial record is never modified.

### Fields

| Field | Type |
|--------|------|
| _id | ObjectId |
| transactionId | String |
| fraudProbability | Number |
| anomalies | Array |
| graphFindings | Array |
| aiExplanation | String |
| calculatedRisk | Number |
| decision | String |
| analyzedAt | Date |

Example anomalies

- Duplicate Transaction
- Future Timestamp
- High Velocity
- Location Conflict
- Amount Anomaly
- Money Laundering Loop

# 5. Risk Profiles Collection

## Purpose

Maintains a continuously updated fraud risk score for every customer.

Instead of recalculating every transaction, the platform updates this profile.

### Fields

| Field | Type |
|--------|------|
| _id | ObjectId |
| userId | ObjectId |
| currentRiskScore | Number |
| riskLevel | String |
| warningCount | Number |
| fraudCaseCount | Number |
| accountStatus | String |
| lastUpdated | Date |

↓

↓

↓

↓

# Why We Need Each Collection

## Users

Stores authentication and user profile information.

---

## Accounts

Provides virtual bank accounts for the Banking Simulator.

---

## Transactions

Stores the original financial transaction.

This data should never be modified.

---

## Fraud Analysis

Stores AI predictions, anomaly detection results, graph findings, and explanations.

Separating this from Transactions keeps financial records clean and makes the system easier to maintain.

---

## Risk Profiles

Maintains the customer's current fraud risk score.

This avoids recalculating historical transactions every time.

---

## Fraud Cases

Allows fraud analysts to investigate suspicious accounts.

---

## Alerts

Notifies customers and analysts about important fraud-related events.

---

## Audit Logs

Records every important system activity for traceability and compliance.
